Failed calls and fallback attempts consume that same single reservation. A repeated protected identity returns the existing reservation; the Edge refuses to dispatch that replay. An ambiguous prior call must be recovered through existing Activity evidence, without automatically repeating the paid dispatch.

The protected allowance uses UTC calendar months. Prior protected consumption and the first-enrollment timestamp survive off/on toggles and plan changes. Requests made while protection is off remain recorded but do not consume the protected allowance. Unenrolled legacy calls without an Activity job remain distinct admissions when they create distinct messages; a separate server-derived rate bucket bounds them to **30 new admissions per minute**, with a safe HTTP **429** and no provider dispatch on denial. Their compatibility path does not gain the protected Activity identity guarantee.

The migration rejects legacy service-only chat inserts that would bypass an enabled policy after an Edge rollback. Admission identity/scope/timestamps/lineage are immutable; protected current-period rows cannot be deleted to refund allowance, including during a temporary disablement. Completion and usage telemetry updates remain allowed. Current enabled-invalid subscription/plan state fails closed. The UI distinguishes the protected period from ordinary telemetry and derives a genuine Needs You exception for incompatible active policy state.

The verified implementation scope is **explicitly enrolled, Activity-backed monthly cloud-chat request admission only**. Token, monetary, seat, device, storage and capability allowances remain commercial capture. A request reservation does not cap the number or billed cost of fallback provider attempts inside that turn. No customer was enrolled or paid model called to produce this evidence.

## REUSABLE LESSON CANDIDATES — advisory only

1. **Tenant context is a service boundary.** Replacing a workspace label does not retarget cached clients, composer history or queued commands. Rebuild tenant-bound dependencies, clear prior data, fence late responses and test return/restart as well as entry.
2. **Every admission path needs the same authority.** Explicit Core grants must govern privileged reads and writes even when a staff member also has a customer owner role. Inspect direct grants and underlying RPCs; a secure new wrapper cannot protect an older callable bypass.
3. **Recheck authority after remote work.** A valid grant at request start can expire or be revoked during a provider read. The response boundary and retained UI routes must fail closed when authority changes.
4. **Account lifecycle requires observed prerequisites.** An identity record is not an active customer. Recoverable provisioning must identify partial invites, missing membership, disconnected providers, unverified adapters and required human decisions without fabricating progress or deleting a shared Auth identity after a downstream failure.
5. **Different evidence classes must remain separate.** Catalog discovery, activation metadata, live connection verification, entitlement, execution authorization and successful runtime use answer different questions. Stale or contradictory fields cannot be compressed into a reassuring healthy flag.
6. **Exact source is part of a test result.** Preserve PR head, generated merge-ref SHA, migration digest, artifact identity and deployed SHA separately. A passed step inside a failed CI job, an old golden upload or a local mutable working-tree run is not final acceptance.
7. **Deployed entrypoints override file presence.** Read the live Edge entrypoint and bundled files before relying on an API found in a repository. A deliberately narrowed deployment can omit an otherwise implemented handler.
8. **Unknown finance is not zero.** Manual amounts, estimates, reconciled billed costs, unmatched samples and separate currencies need explicit semantics. Configured allowance terms do not establish complete admission enforcement or authoritative margin.
9. **Infrastructure rollback boundaries differ.** Restoring a Vercel alias does not revert Supabase schema, grants, audit or customer records. Preserve recovery anchors and use scoped forward fixes/revocation when destructive database rollback would discard valid data.
10. **Launch is part of the product journey.** An implemented Home and passing isolated screen tests do not prove that an authorized owner reaches it after authentication. Verify the actual startup selector and active-chat restoration separately, then exercise them with real owner and customer sessions.
11. **Neutral names can hide retired dependencies.** A deployment ledger tied to ProjectOS project/version storage cannot become Core release truth through a new UI label. Use the existing immutable audit chain for narrowly validated current provider observations; preserve historical records without creating new retired-project links or a parallel ledger.
12. **Check every serving alias.** Disabling automatic custom-domain assignment does not guarantee generated Vercel project/branch aliases stay unchanged. Bind the immutable deployment, canonical hostname and generated aliases to their observed served source separately.
13. **Commercial terms require an admission boundary.** A stored plan or “block” option does not stop provider dispatch. Name the covered unit and execution path, reserve durably before dispatch, and treat an ambiguous prior call as an existing operation to recover. A request-count guard must not be presented as a monetary, token or whole-platform spending guarantee.
14. **Migration versions are part of integration truth.** Exact applied SQL bytes are necessary but do not guarantee that provider migration versions match source filenames. Compare complete version/name sets before promotion. When a provider assigns a different version to otherwise identical new SQL, use a bounded source-only filename/reference correction and rerun ordered replay; preserve prior receipts and avoid DDL replay or fabricated history repair.

These are proposed procedures/failure lessons derived from inspected defects and bounded tests. They are not automatic policy or new permission. Promotion requires review of the exact supporting source and applicable final runtime evidence.
